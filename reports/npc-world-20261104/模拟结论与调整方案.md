# 无玩家干预的七日天下模拟

结论：现有系统确实能自行结盟、断交、议和、争地和出现强宗，但长期运行会滑向人口萎缩、宗门频繁换皮、大片领地无主。目前还没有达到“人物与宗门能积累历史、兴衰有因果”的小世界目标。

这次只做隔离模拟和诊断，没有修改业务源码、正式游戏存档或玩法数值，也没有发送真实群消息。

## 怎么模拟

- 三个独立新世界，随机种子104、233、907，各推进7个游戏日，每分钟执行一次真实 `fakeTick`，共30,240个分钟步。
- 正常执行修炼、突破、购物、补货、税收与繁荣、宗门产出及维护、外交、战争、人员入宗/离宗、魔窟和灵兽等现有流程；按原规则处理夜间暂停。经济结算按其独立定时器运行。
- 不加入真人、玩家宗主、小队、玩家收入或玩家操作。公开/古钥秘境没有为模拟群额外开启白名单，不代表已经测试过这些玩法联动下的长期演化。
- 使用新档自身的随机性格、人员和领地分配。新档原有3小时历史预演保留，但不计入本报告的七日新增事件。
- 为加速，JSON落盘和Redis换成内存适配器，推进时钟加速，随机数固定；没有删掉玩法更新步骤。这是行为与平衡模拟，不是机器人重启、真实Redis或断电恢复测试。
- 每小时保存一次人口、宗门、领地、财力与盟约快照，另外完整记录战争及主要势力事件。
- 后续给世界甲增加只读的出生/死亡观测钩子重跑，战争数、人口终值等与原跑一致。另做一组“只关闭自动宗门战争”的诊断对照，其他流程继续运行。

源码快照与当前核心文件比对一致；复制时的文件指纹保存在 `source-sha256.json`。模拟脚本为同目录的 `autoworld.mjs`，应放到隔离插件根目录执行，不能直接拿正式目录运行。

一次总部覆灭可能使多个小区同时无主或易主，所以领地变动次数不等于成功攻打次数。一次议和可以结束多场战事，也可以只解除敌对，所以议和事件数与议和结束的战争数不同。

模拟没有记录到未捕获异常、负数宝库或同一NPC同时占用多个战争名单。此结果说明这几项检查在样本中通过，不代表所有玩法状态都已被穷举验证。

## 已经有的小世界效果

不是“完全没有戏”。三组都能出现合作与翻脸，强宗也能扩张。世界甲的御兽宗曾占19/30处领地；另外两组的最大势力也曾占到12处。

但御兽宗的后续揭示了问题：

| 世界甲经过时间 | 御兽宗状态 |
| --- | --- |
| 60小时 | 16处领地，13名门人 |
| 65小时 | 19处领地，8名门人 |
| 66小时 | 19处领地，9名门人 |
| 66小时03分 | 触发“管理层尽数陨落”，全宗被判灭门 |
| 67小时快照 | 同一宗门编号已变成太虚楼，0处领地、1名门人 |

这段衰落没有走成“治理压力增大—内部矛盾—部分势力分裂—其他宗门乘虚而入”，而是核心名单一空，19处领地直接清掉，再出现一个新名字。它会制造变化，却很难留下连续的势力历史。

## 失衡原因

### 1. 日常致死行为是主要消耗，不能只修攻打判断

世界甲七日共记录1,176次人物死亡、1,053次新人物进入存活名单，人口账目为：148＋1,053－1,176＝25。

死亡来源如下：

| 死亡原因 | 人次 |
| --- | ---: |
| 仇杀 | 536 |
| 劫道 | 172 |
| 杀人越货 | 160 |
| 灭口 | 110 |
| 寻仇 | 56 |
| 劫修 | 50 |
| 战俘处决 | 39 |
| 每轮战场战死 | 20 |
| 战后战死判定 | 17 |
| 矿难 | 16 |

当前 `genMurder` 选中目标后直接抢夺并调用 `killPerson`，没有先比较双方战力，也没有执行正常胜负流程。日常事件总量不会随着人口减少而自然减少，因此人数越少，每个人被危险事件反复抽中的压力越大。

补员也有明显的“换人”成分：世界甲1,053名新增人物中，579名来自弟子死亡后的立即替补，177名来自旧式换皮重建，267名来自定时入世，30名来自其他入宗补充。场面很热闹，但许多人物来不及积累自己的关系和经历。

诊断对照中，只关闭自动宗门战争，七日人口仍从148降到49，并发生923次日常死亡，其中490次是仇杀。对照中的随机轨迹会因关闭战争而分叉，不能将两组差值直接当作战争的净因果效应；但它足以表明，日常系统本身就会显著消耗人口。

相关位置：`components/fake_data.js` 的 `genMurder`、`EVENT_GENS`、`killPerson`。

### 2. 另一条旧式灭门与换皮重建逻辑仍在运行

之前重构统一了“总部被攻破”的永久灭门分支。此次长跑又暴露出 `rebuildSettle` 中的另一条路径：宗主、副宗、太上名单都没有存活者时，即使总部没有被攻破、宗内还有普通门人，也会清空领地，随后约30分钟换名重建。

三组各有177、164、163次这种循环，远多于8、6、4次真实攻破总部。这是后期宗门寿命短、地盘大片无主的直接来源之一。

你的硬设定继续成立：**总部被攻破，原宗门必须灭门。** 需要调整的是“总部完好但核心职位空缺”的继任流程，不是把已经被攻破的宗门救回来。

相关位置：`components/fake_data.js` 的 `rebuildSettle`、`promoteSettle`。

### 3. 外交会变化，但缺少持续时间与一致的身份

世界甲在开局31分钟先记录“紫霄殿与御兽宗结盟”，同一分钟又记录两宗断交。三组分别出现11、10、12次相邻日志中的同分钟结盟后断交。

当前一次外交推进可以刚创建盟约，后面的断交分支又马上选中这对宗门。旧式重建只清空本宗的盟友/敌人列表，其他宗门仍可能保留对旧编号的关系；而这个编号已经换成另一个宗门名字。

三组分别有52、9、54个每小时快照包含敌友关系重叠记录。时间线中的“单方关系残留”按原存档展示，没有替系统美化或修正。

相关位置：`components/sect/diplomacy.js` 的 `aiDiplomacy`；`components/fake_data.js` 的旧式重建路径。

### 4. 实派兵力缩水后仍会开打，实际确有送兵

按宣战后已经派到场的双方阵容观察，三组共164场的攻方初始战力低于已部署守方的85%。这些战事最终3场获胜、93场败退，其余议和或中止。

这不是整场胜率测算，也没有预知后续援军；它记录的是当前引擎实际发起时的阵容。结果支持上一轮检查发现的问题：选敌按可用总兵力估算，实际出兵缩水后，没有最后一遍按实派阵容复核。

相关位置：`components/sect/war.js` 的 `aiSectOffensePower`、`spawnAiSectAttacks`、`startSectAttack`。

## 建议按这个顺序调整

### 第一批：先让世界能长期存活

1. **危险行为走真实胜负和个人冷却。** 仇杀先看目标、双方战力与关系，打不过时退让或等待机会；击败目标后才判断是否致死。普通冲突更多产生伤势、损失、结怨或逃脱，旧仇和灭门之仇可以保留更激烈的后果。保持江湖动态的更新频率，单独限制致死行为，避免小人口时反复抽杀同几个人。
2. **总部完好时先处理继任。** 核心空缺先由在世门人竞争或临时掌事，允许夺权和内耗。确实无人延续时才自然消亡；新宗门另建身份，不沿用旧编号换名。总部被攻破仍永久灭门。
3. **出兵前按实际阵容复核。** 把愿意参战、预算、路程和封锁之后真正能到场的兵力用于最后判断。盟友援军只有实际派出才算。明显劣势时积蓄、议和或换目标，而不是硬送；势均力敌的战争仍可发生。
4. **外交关系成对更新并保留记忆。** 盟友与敌对互斥，灭门和新建时清理双方旧引用；新盟约不在同一次推进立刻随机作废。议和后的停战覆盖双方的总部与全部小区，避免换个目标立即重开。仇怨、救援、抢地和背约应影响之后的选择。

主要涉及 `components/fake_data.js`、`components/sect/war.js`、`components/sect/diplomacy.js` 及相应回归测试；沿用你刻意设置的NPC成长和资源优势。

### 第二批：让“分合”来自利益与治理

第一批稳定后，再增加以下因果链，不靠强制刷新霸主或随机灭门制造变化：

- 弱宗因为共同威胁抱团，盟约因共同收益维持；长期受压或利益分配不均才逐步瓦解。
- 强宗扩张后出现远地调兵、维护、忠诚与管理压力；边地掌事在拥有门人、资源和地盘时才可能自立。
- 内部分裂应带走真实人员与一部分真实领地，并触发真实争夺；不是只换宗门名字。
- 战败有恢复与重整的阶段，战胜也要花时间治理；老人物可以远遁、投宗、复仇或支持新主。
- 允许短期形成霸主甚至一统，后续分裂由上述压力累积触发，不设置“占太多地就自动清空”的剧本。

这些属于下一批新机制，本次没有实现或伪造其模拟结果。

## 后续验收

每批调整后重新跑多个种子的7日与更长周期：检查人物是否能留存并形成成长经历、宗门能否度过核心更替、领地能否长期被经营、停战与盟约是否有持续性，以及实际扩张和分裂是否发生。继续检查NPC兵力独占、预算非负、俘虏与灭门清理、结算幂等。

不能只用“结盟次数多”“灭门次数多”作为成功标准。需要在同一条时间线上看见强宗崛起、弱宗合作、战后休养、内部矛盾和新势力接续，同时没有人口与治理的持续崩溃。
